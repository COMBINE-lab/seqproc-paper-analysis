# Repository relevance audit

**Scope:** every one of the 136 git-tracked files in `seqproc-paper-analysis` (branch `repo-cleanup-for-review`), classified by whether it is traceable to the seqproc paper. Nothing is removed here — this only flags.

**Method:** nine per-directory auditor agents traced each file to `/home/ubuntu/paper` (README artifact map + `\includegraphics`/`\label`/number greps + import/consumer greps); every file a first pass flagged was then handed to an independent skeptic that tried to *rescue* it (this recovered 11 files, e.g. `splitpipe_full_concordance.py`, `tolerance_sweep.sh`, `splitseq_singleend.mb`). Finally I ground-truthed the figure claims directly against the compiled paper, which corrected several automated verdicts (see note below).

**Verdict tally:** ✅ **102 relevant** · 🚩 **20 flagged** · ⚠️ **14 keep-with-note** (provenance / prose-backing, not a distinct paper artifact).

**"The paper" = two targets.** The *preprint* (`sections/*.tex` + `seqproc.tex`) is the active deliverable; the *thesis* (`Thesis/ch6_results.tex`) is done. This matters because the **preprint displays only three figures** — `fig:seqproc_workflow` and `fig:illustrative_example` (hand-drawn schematics in `paper/Figures/`, not generated by this repo) and **`fig:count_concordance`** (the one data figure, from `count_concordance.py`). Everything else in the preprint is LaTeX tables and prose numbers. The recovery / hamming-vs-edit / discordant figures the repo generates are `\includegraphics`'d **only in the thesis** (`ch6_results.tex`), so they are relevant-to-thesis, not "old" — but the *merged* `downstream_concordance` figure and the legacy `fig1/fig_performance_table` images are in **neither** paper.
